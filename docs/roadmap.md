# CLI 实施路线图

更新日期：2026-11-05。本文是计划，不代表已完成实现或验证。职责以仓库根 `AGENTS.md` 为准。

## 目标

CLI 独立提供基础命令，通过可选下载、启动或连接 Host 获得扩展能力。HomeWorld 不依赖 CLI。

基础命令规划见 [CLI 子命令设计](command-design.md)：新增 `bi` 快捷入口并保留 `bootidea`，以 `app`、`repo`、`env` 分别管理软件、Git 仓库与开发环境，辅以 `config` 和 `doctor`。这些能力独立于 Host；第一阶段先打通软件安装、仓库克隆、项目环境准备和打开项目的流程，完整命令清单不代表首期全部交付。

## 实施顺序

1. 盘点基础命令和 Host 扩展命令，明确无 Host、离线和版本不兼容时各命令的行为。
2. 配合 Host 定义协议与发布契约，将现有宿主装配、服务启动和服务端传输迁出本项目。
3. 实现 Host 协议客户端，将扩展调用改为进程通信，移除宿主运行引擎的强制编译依赖。
4. 设计并实现 Host 安装、版本、状态、启动、连接与停止命令；参数与命令名称另行确定。
5. 在 Host 扩展管理协议稳定后提供安装、授权、启停和日志命令，再接入 harness 任务操作。

## 验收标准

- 无 Host 时仍可构建、启动并使用基础命令。
- 扩展功能缺少 Host 时给出安装提示；协议不兼容时明确报告，不静默降级。
- 管理自行启动的实例，不停止 HomeWorld 或其他消费者拥有的进程。
- 协议客户端依据共享契约及测试样例实现，不依赖 Host 内部存储结构。

## 依赖与当前差距

当前 CLI 内嵌 Host 库并承载 `serve`，需要在 Host 独立入口可用后迁移。Host 发布包、CLI 发布包和 harness 插件包保持清晰区分。
